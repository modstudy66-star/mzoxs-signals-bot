# بوت MZOXS Signals

بوت تلغرام مكتوب بلغة **Python** باستخدام مكتبة **python-telegram-bot**. يدير عروض الإشارات، وينشر العروض المصورة في القناتين، ويبيع اشتراكاً شهرياً في القناة الخاصة عبر **Telegram Stars**، ويرسل رابط دخول فردياً إلى المشترك فور تأكيد الدفع.

> **اسم القناة الخاصة المقترح:** `MZOXS Signals VIP`. أنشئها كقناة خاصة في تلغرام، ثم ضع رقمها الرقمي في `PRIVATE_CHANNEL_ID`.

> **تنبيه أمني:** لا ترفع ملف `.env` إلى GitHub أو إلى أي مستودع عام، ولا ترسل توكن البوت أو كلمة مرور الاستضافة أو مفتاح API في المحادثات. أضف الأسرار مباشرة إلى متغيرات خدمة الاستضافة.

## الوظائف

| الوظيفة | السلوك |
| --- | --- |
| `/start` | يعرض أزرار **العروض اليومية** و**القناة الخاصة** و**تواصل معنا**. |
| الاشتراك المدفوع | يصدر فاتورة بقيمة **5500 نجمة** لمدة **30 يوماً**. |
| الوصول بعد الدفع | بعد تأكيد الدفع من تلغرام، يُسجل البوت العملية ويُرسل رابط دعوة فردياً صالحاً لمدة ساعة وعضو واحد. |
| القناة المجانية | القناة المضبوطة افتراضياً هي `@MZOXS_SIGNALS_FREE`. |
| القناة الخاصة | القناة المضبوطة بالاسم `MZOXS Signals VIP`، وتحتاج فقط إلى ضبط معرّفها الرقمي. |
| لوحة الإدارة `/admin` | تضيف عرضاً بالترتيب: صورة، ثم نص، ثم رابط. يحفظه البوت وينشره فوراً في القناة المجانية والخاصة. |
| `/stats` | يعرض للمدير عدد المستخدمين، المشتركين النشطين، الدفعات المسجلة، وإجمالي نجوم الدفعات. |
| الجدولة | يرسل البوت عرضاً بالتناوب للمستخدمين الذين بدأوا البوت في 09:00 و17:00 و22:00 بتوقيت `Asia/Baghdad`. |
| انتهاء الاشتراك | يفحص الاشتراكات المنتهية يومياً ويحاول إخراج العضو من القناة الخاصة. |
| قاعدة البيانات | يحفظ المستخدمين والعروض والمدفوعات في SQLite. |

## هيكل الملفات

```text
mzoxs_signals_bot/
├── bot.py              # منطق البوت، الدفع، الإدارة، النشر والجدولة

├── requirements.txt    # مكتبات Python
├── .env                # إعداد محلي، يحتوي قيماً بديلة فقط

├── .gitignore          # يمنع رفع الأسرار وقاعدة البيانات
├── railway.json        # أمر تشغيل البوت وسياسة إعادة التشغيل في Railway
└── README.md           # دليل التشغيل والنشر
```

## إعداد القنوات قبل التشغيل

أنشئ القناة المدفوعة باسم **MZOXS Signals VIP** واجعلها خاصة. أضف البوت مديراً في القناتين، ثم امنحه الصلاحيات التالية.

| القناة | الصلاحيات المطلوبة للبوت | السبب |
| --- | --- | --- |
| `@MZOXS_SIGNALS_FREE` | **نشر الرسائل** | ينشر العرض المصور الجديد تلقائياً. |
| `MZOXS Signals VIP` | **نشر الرسائل** و**دعوة المستخدمين عبر الروابط** و**حظر/إزالة المستخدمين** | ينشر العروض، ينشئ رابط الدخول بعد الدفع، ويسحب الدخول بعد انتهاء الاشتراك. |

يعتمد إنشاء رابط فردي على واجهة `createChatInviteLink` في Telegram Bot API، ولذلك لا بد من أن يكون البوت مديراً مع صلاحية الدعوات في القناة الخاصة. [1]

> لا يكفي رابط دعوة خاص لاستخراج `PRIVATE_CHANNEL_ID`. استخدم أداة موثوقة لإظهار معرفات تلغرام، أو اقرأ معرف القناة من تحديث البوت أثناء الاختبار. معرف القنوات يبدأ عادةً بـ `-100`.

## إعداد ملف `.env`

افتح `.env` وضع قيمك الحقيقية. لا تضع الأقواس أو علامات الاقتباس حول القيم.

```dotenv
BOT_TOKEN=123456789:ضع_توكن_البوت_الحقيقي_هنا
ADMIN_IDS=123456789
FREE_CHANNEL_ID=@MZOXS_SIGNALS_FREE
FREE_CHANNEL_URL=https://t.me/MZOXS_SIGNALS_FREE
PRIVATE_CHANNEL_NAME=MZOXS Signals VIP
PRIVATE_CHANNEL_ID=-1001234567890
CONTACT_URL=https://t.me/your_username
DATABASE_PATH=data/bot.db
TIMEZONE=Asia/Baghdad
MONTHLY_PRICE_STARS=5500
```

| المتغير | القيمة المطلوبة |
| --- | --- |
| `BOT_TOKEN` | توكن البوت من BotFather. احفظه كسِر. |
| `ADMIN_IDS` | رقم حساب مدير البوت، وليس `@username`. يمكن وضع أكثر من رقم بفاصلة. |
| `FREE_CHANNEL_ID` | اسم مستخدم القناة المجانية مع `@` أو معرفها الرقمي. القيمة المضبوطة هي `@MZOXS_SIGNALS_FREE`. |
| `PRIVATE_CHANNEL_ID` | معرف القناة الخاصة الرقمي، مثال `-1001234567890`. |
| `PRIVATE_CHANNEL_NAME` | الاسم الظاهر للمستخدمين في رسائل الاشتراك. القيمة الافتراضية `MZOXS Signals VIP`. |
| `CONTACT_URL` | رابط الدعم، مثل `https://t.me/username`. |
| `DATABASE_PATH` | محلياً: `data/bot.db`. على Railway بعد ربط وحدة تخزين: `/data/bot.db`. |
| `TIMEZONE` | المنطقة الزمنية للجدولة، والقيمة الحالية `Asia/Baghdad`. |
| `MONTHLY_PRICE_STARS` | قيمة الاشتراك بالنجوم؛ مضبوطة على `5500`. |

## التشغيل محلياً

يتطلب المشروع Python 3.10 أو أحدث. من داخل مجلد المشروع شغّل التالي:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python bot.py
```

افتح البوت من حساب المدير ثم أرسل `/admin`. في أول تشغيل، ينشئ التطبيق قاعدة SQLite تلقائياً في المسار المحدد داخل `DATABASE_PATH`.

## استخدام لوحة الإدارة

بعد إرسال `/admin`، اختر **إضافة عرض مصور**. يتبع البوت تسلسلاً واضحاً يمنع النشر الناقص:

| الخطوة | ما ترسله الإدارة | ما يفعله البوت |
| --- | --- | --- |
| 1 | صورة العرض | يحفظ `file_id` الخاص بتلغرام لإعادة إرسال الصورة بكفاءة. |
| 2 | نص العرض | يحفظ النص حتى 900 حرف ليكون مناسباً كشرح للصورة. |
| 3 | رابط يبدأ بـ `https://` أو `http://` | يحفظ الرابط في زر **فتح العرض**. |
| 4 | لا شيء إضافي | يحفظ العرض في SQLite وينشر الصورة والنص والزر فوراً في القناة المجانية والخاصة. |

يمكن إلغاء عملية الإضافة في أي لحظة بالأمر `/cancel`. زر **حذف عرض** يعطل العرض من الظهور أو الإرسال لاحقاً، لكنه لا يمسح سجل البيانات التاريخي.

## الدفع والوصول للقناة الخاصة

عند نقر المستخدم **القناة الخاصة**، يعرض البوت اشتراكاً لمدة 30 يوماً بسعر 5500 نجمة. ينفذ البوت تحققاً من نوع المنتج والعملة `XTR` والمبلغ قبل قبول الدفع، ثم ينتظر حدث `successful_payment` من تلغرام قبل تسجيل الاشتراك أو إرسال رابط الدخول. فواتير Telegram Stars تستخدم `XTR` ولا تتطلب `provider_token`. [2]

إذا كان للمستخدم اشتراك فعال وتجدد، يضيف البوت 30 يوماً بعد تاريخ انتهاء اشتراكه الحالي بدلاً من إضاعة الأيام المتبقية. كما يخزن رقم معاملة تلغرام الفريد، فلا يحتسب إشعار الدفع نفسه مرتين.

## النشر على Railway

يعمل هذا البوت عبر long polling، لذلك يجب أن يعمل **نسخة واحدة فقط** من الخدمة. لا تحتاج إلى نطاق عام أو Webhook.

> **ضروري:** التخزين العادي للخدمة في Railway مؤقت بين عمليات النشر. اربط وحدة تخزين دائمة ثم استخدم `/data/bot.db` حتى لا تُفقد بيانات SQLite والمدفوعات والمشتركين. تؤكد وثائق Railway أن البيانات التي تحتاج إلى البقاء بين عمليات النشر يجب أن تُحفظ في Volume. [3]

### 1. رفع الكود إلى GitHub

فك ضغط المشروع، ثم أنشئ مستودع GitHub خاصاً وارفع الملفات إليه. لا ترفع `.env`؛ الملف مستثنى عبر `.gitignore`. يمكنك رفع `.env.example` لأنه يحتوي أسماء المتغيرات وقيم مثال فقط.

```bash
git init
git add bot.py database.py requirements.txt railway.json README.md .env.example .gitignore
git commit -m "Deploy MZOXS Signals bot"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

### 2. إنشاء خدمة Railway

سجّل الدخول إلى Railway، ثم أنشئ مشروعاً جديداً واختر النشر من مستودع GitHub. اختر مستودع البوت الذي رفعته. ملف `railway.json` في المشروع يضبط أمر التشغيل إلى:

```text
python bot.py
```

وتدعم Railway تعريف أمر البدء وسياسة إعادة التشغيل من ملف الإعدادات المرفق. [4]

### 3. إضافة متغيرات البيئة

من صفحة الخدمة افتح تبويب **Variables** ثم أضف المتغيرات التالية. بإمكانك استخدام محرر RAW، لكن استبدل القيم البديلة بالقيم الحقيقية ولا تلصق أي سطر تعليق.

```dotenv
BOT_TOKEN=ضع_توكن_البوت_الحقيقي
ADMIN_IDS=رقم_معرفك_الرقمي
FREE_CHANNEL_ID=@MZOXS_SIGNALS_FREE
FREE_CHANNEL_URL=https://t.me/MZOXS_SIGNALS_FREE
PRIVATE_CHANNEL_NAME=MZOXS Signals VIP
PRIVATE_CHANNEL_ID=-100معرف_القناة_الخاص_بك
CONTACT_URL=https://t.me/your_username
DATABASE_PATH=/data/bot.db
TIMEZONE=Asia/Baghdad
MONTHLY_PRICE_STARS=5500
```

تجعل Railway هذه القيم متاحة للتطبيق كمتغيرات بيئة وقت التشغيل، ويمكنك حماية قيمة `BOT_TOKEN` أكثر بخيار **Seal** داخل صفحة المتغيرات. [5]

### 4. ربط وحدة تخزين دائمة

من خدمة البوت في Railway أضف **Volume** واحداً واجعل مسار الربط:

```text
/data
```

بعدها تأكد أن المتغير `DATABASE_PATH` يساوي `/data/bot.db`، ثم نفذ النشر. لا تشغل أكثر من Replica واحدة: كل خدمة متصلة بوحدة التخزين الدائمة لها Volume واحد، كما أن وجود نسختين من بوت long polling قد يسبب تكرار معالجة تحديثات تلغرام. [3]

### 5. النشر والتحقق

بعد حفظ المتغيرات، راقب Logs حتى يظهر السطر الذي يفيد ببدء البوت. بعد ذلك:

1. أرسل `/start` للبوت من حساب عادي وتأكد من ظهور القائمة.
2. أرسل `/admin` من الحساب الموجود في `ADMIN_IDS`.
3. أضف عرضاً تجريبياً: صورة، نص، ثم رابط؛ تحقق من وصوله إلى القناتين.
4. نفذ `/stats` وتأكد من ظهور الإحصاءات.
5. جرّب الدفع بحساب اختبار مناسب قبل الاعتماد على عمليات حقيقية.
6. تأكد من أن البوت مدير في القناة الخاصة ويملك صلاحيات الدعوات وإزالة الأعضاء قبل اختبار الدفع.

## الجدولة اليومية

| الوقت حسب `TIMEZONE` | المهمة |
| --- | --- |
| 09:00 | إرسال عرض واحد بالتناوب إلى المستخدمين النشطين الذين بدأوا البوت. |
| 17:00 | إرسال العرض التالي. |
| 22:00 | إرسال العرض التالي. |
| 02:05 | فحص الاشتراكات المنتهية ومحاولة سحب دخول القناة الخاصة. |

العرض الجديد الذي تضيفه الإدارة يُنشر فوراً أيضاً في **القناة المجانية والقناة الخاصة**؛ هذا النشر مستقل عن الجدولة اليومية للمستخدمين.

## ملاحظات مهمة

لا توجد حاجة في هذا الإصدار إلى بيانات دخول Replit أو مفتاح Twelve Data، إذ إن المتطلبات الحالية لا تجلب أسعاراً أو تنشئ توصيات آلية من واجهة خارجية. لا تضف تلك البيانات إلى `.env` ولا إلى Railway إلا عندما تُضاف ميزة تستخدمها فعلياً.

إذا تمت مشاركة أسرار حقيقية سابقاً في محادثة أو مكان عام، فالأفضل تدويرها من المصدر: أنشئ توكن بوت جديداً من BotFather عند الحاجة، وغيّر كلمات المرور أو مفاتيح API التي يُشتبه بأنها تعرضت للكشف.
